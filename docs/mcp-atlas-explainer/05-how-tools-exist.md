# 程序以什么形式放在机器上

「有一个 MCP 工具」在公开代码里分成几段。镜像构建时装包，少数程序要等启动才去取代码，调用时用本机标准输入输出，子进程需要时才自己访问外网。

## 大多数包在构建镜像时已经装好

沙箱的 Dockerfile 在构建时运行一份安装脚本。脚本用 `npm install -g` 装带版本号的 Node 包，用 `uv tool install` 装带版本号的 Python 包。注释写，预先装好是为了省掉大约一分钟的启动下载。脚本末尾写，从 GitHub 地址安装的那些被跳过。

装进镜像的是程序。接口密钥不进镜像。无论拉取现成镜像还是自己构建，密钥都在容器启动时从 `.env` 注入。入口脚本把模板里的变量换成当时的环境变量，再启动服务。

同一次构建把数据目录挪到容器内的 `/data`。那里有 CSV，例如 `Barber Shop.csv`，也有 memory 程序用的一份 JSON。读文件和记忆的默认路径指向这些容器里的文件。

## 有的 git 克隆发生在构建，有的发生在启动

构建镜像时，Dockerfile 读 `git_submodule_info.csv`，把 8 个仓库克隆到 `/data/repos/`，并检出固定提交。`.gitmodules` 是同一批：`balldontlie-mcp`、`mcp-server-calculator`、`metmuseum-mcp`、`mongodb-mcp-server`、`slackr`、`snake-game`、`storyteller`、`tree-sitter-diff`。它们是题目要读的代码和数据，给 filesystem 和 git 用。它们不是那 36 个 MCP 进程。`balldontlie` 这个词会出现在某些题的允许名单里，模板并不启动一个叫 `balldontlie` 的 MCP 程序。你如果直接用预构建镜像，这 8 份检出已经在镜像层里，每次启动不会再克隆。提交号在证据页。

另外 4 个 server 的启动参数直接指向 GitHub，预装脚本又跳过这类安装。容器起来、客户端按命令拉起子进程时，才会去取这些地址。它们是 `pubmed`、`weather-data`、`github`、`weather`。`weather` 不需要密钥。`weather-data` 需要密钥。两个都和天气有关，是两行不同的命令。

**这 4 个。** 是什么：启动命令指向 git、预装脚本声明跳过的 MCP server，子进程被拉起时才去取代码。不是什么：不是构建镜像时克隆进 `/data/repos` 的那 8 个题目仓库。

## 本机标准输入输出

模板里每一项都是一条本地命令。沙箱用 MCP 客户端拉起这些进程，经标准输入输出收发调用。模型不连接这些进程。模型只和 harness 对话。harness 用网页请求访问沙箱的 `/call-tool`。沙箱再写给本机子进程。

端口 1984 上的网页接口是沙箱自己的。它不是把上游厂商的地址原样转出去。

## 子进程内部才可能访问外网

进程跑起来之后，有的只碰 `/data`。有的会发出自己的网页请求。会离开容器的，包括带了外部服务密钥的程序，也包括不需要密钥、用途就是查询公开资料的程序。那 20 个不要求密钥的里面，8 个按模板只碰容器里的文件或计算，12 个会匿名出去。名单在 [06-network-and-keys.md](06-network-and-keys.md)。论文第 3.1 节写，任务打到真实的线上端点。`data_exports/README.md` 写，许多 MCP 程序连接的是外部服务。某个包具体请求哪一台主机，看那个包自己的实现。这份说明没有逐个打开那些安装包。

沙箱对一部分工具结果做缓存，默认大约 48 小时，代码里的常数是 `CACHE_TTL_HOURS = 48`。arxiv、cli-mcp-server、filesystem、git 在这份缓存名单里被注释掉了。缓存只是同一条调用在这段时间里可以复用上次的返回。请求如果发生，仍是那个 MCP 进程自己发出的。

论文还写，他们评测用的容器有出网允许列表。公开仓库的文件名里没有防火墙清单。变更记录写，内部用另一套按题开沙箱的代理，那个代理不在公开发布里。公开构建文件能确认的是：包装在镜像里，进程由本地命令启动，密钥在运行时注入。

## 题面里的名字不一定有进程

公开题的允许名单里还有 25 个工具名，前缀是 `anili`、`balldontlie`、`f1-mcp-server`、`rijksmuseum-server`。当前模板不启动这 4 个程序。它们只是名单上的字符串。容器不会为它们起进程，所以也没有「再去访问外网」这一步。公开参考轨迹里，这 4 个前缀一次都没有被调用。为什么这 4 个还留在题目表里，见 [04-from-36-to-300.md](04-from-36-to-300.md)，提交号在证据页。

## 题面不会拿去请求上游网站

默认是这四步。题面是自然语言，脚本把它放进一条用户消息。模型返回函数调用，名字来自它看见的工具列表。harness 把这个名字提交到沙箱的 `/call-tool`。沙箱用标准输入输出调用本机子进程。子进程若需要，再自己去访问外网。

**题面。** 是什么：交给模型的一段自然语言。不是什么：不是发往 Brave、GitHub 或 Notion 的网页请求。那些网站上的请求如果发生，发生在对应的 MCP 子进程里面。

仓库里另有 `services/mcp_eval/convert_tasks_to_harbor.py`。它假设镜像在 `http://localhost:<端口>/mcp` 上提供另一种接口，并用一份名单文件限制工具。那不是沙箱的 `/call-tool`，也不是 README 的默认跑法。
