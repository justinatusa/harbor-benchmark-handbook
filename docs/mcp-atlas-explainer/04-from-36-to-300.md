# 一个 server 有很多个 tool

上一页说一只镜像里挂着多个 server。这里解释这些程序公布出来的接口为什么远多过程序个数，以及一道题为什么只把其中一小撮交给模型。

## 程序是一个，接口是一排

配置里每个 server 是一条启动命令。`calculator` 启动计算器。`filesystem` 启动读文件的程序，根目录在 `/data`。`github` 启动管 GitHub 的程序，并把令牌传进去。

沙箱启动后会向这些程序要工具列表。日志里，server 的个数和工具的条数是两个数。前者数进程。后者数这些进程公布的动作。

一个动作的名字写成 `程序名_动作名`。`filesystem_read_text_file` 是读文本，`filesystem_list_directory` 是列目录，两个都挂在 filesystem 上。程序名里用连字符，例如 `brave-search`，所以从第一个下划线切开，前半段是程序名。

README 把完整目录指到一份清单。清单按程序分组。calculator 和 fetch 各有 1 个动作。filesystem 有 14 个。desktop-commander 有 21 个。github 有 33 个。twelvedata 有 35 个。36 个程序的动作加在一起，清单上是 307 个。

论文选程序时写过：一个程序上要有多个相近动作，才放得进干扰项。307 就是这些动作的目录，不是又有 307 个服务，也不是 307 道题。

**36。** 是什么：模板里要启动的 MCP 程序个数。不是什么：不是 tool 的个数。

**307。** 是什么：那份工具目录里的接口总数，36 个程序的动作加总。不是什么：不是每一道题交给模型的个数。也不是对正在运行的 1.2.7 镜像调用 `/list-tools` 当场数出来的。发布 1.2.7 的提交写，exa 还会多暴露一个 `exa_web_fetch_exa`，那份清单里 exa 仍只算 1 个。容器这次没有启动，过程在证据页。

## 220 是题里出现过的名字

论文和数据集卡片写 220 个工具。把公开题的 `ENABLED_TOOLS` 合并，不同的名字也是 220 个。

这个数问的是：公开题的允许名单里，一共出现过多少个不同工具名。它比 307 小，因为目录里有不少动作，没有任何一道公开题把它写进允许名单。参考调用真正打过的名字更少，是 106 个，只是这 220 里的一部分。

220 不能拿去减 307。307 减 220 得 87，这个 87 对不上任何一类工具。两边不是包含关系。

名单里有 25 个名字，前缀是 `anili`、`balldontlie`、`f1-mcp-server`、`rijksmuseum-server`。这 4 个不在当前模板的 36 个启动键里。2025-12-03 的模板曾经有 45 个键，2025-12-15 删掉 9 个，说明写的是当时的公开数据集不再需要它们。删掉的 9 个里，这 4 个的名字还留在后来的题目表里，另外 5 个公开名单里没有。这 25 个出现在 85 道公开题的允许名单里，参考调用一次都没有用过。容器里没有对应进程。模型如果点了它们，没有一个活着的程序可以接。提交号在证据页。

去掉这 25 个，前缀对得上当前 36 个进程的名字是 195 个。195 里有 194 个能在那份 307 的清单里找到。清单没列、题面却有的一个名字是 `clinicaltrialsgov-mcp-server_clinicaltrials_search_studies`。所以 307 减 195 也不是「没用到的工具数」。只在清单里、没有进入公开允许名单的名字是 113 个。113 等于 307 减 194，不等于 307 减 220。

**220。** 是什么：公开题允许名单里出现过的不同工具名，也是论文和数据集卡片写的工具总数。不是什么：不是 307 那份安装目录，也不能拿去减 307。

**25 和 195。** 是什么：25 是允许名单里、当前模板已经没有对应进程的工具名个数。195 是 220 去掉这 25 个之后，前缀还对得上那 36 个进程的个数。不是什么：25 不是又多出来的 4 个正在跑的 server。195 不是 307 减 220。

**194 和 113。** 是什么：公开允许名单和工具目录重合的名字，以及只在目录里、没有公开题写进名单的名字。不是什么：不是又一套要启动的程序。运行时仍按模板里的 36 个来理解。

**45。** 是什么：2025-12-03 那版模板里的 MCP server 个数。不是什么：不是现在要启动的个数。删掉 9 个之后，模板、README 和论文说的都是 36。

## 每题只打开一小撮，里面有干扰项

目录有三百来个动作。每道题若全部交给模型，模型要在整份目录里翻。出题的人给每一题配一份短名单，存在 `ENABLED_TOOLS`。名单里有两类名字。一类是参考解法真正调用过的。一类是放在旁边、参考解法没有用的，论文把后者叫 distractors，这里叫做干扰项。干扰项来自相近的功能，用来看模型会不会选错。

`run_eval.py` 把这列解析成名字，放进请求的 `enabledTools`。harness 向沙箱要到列表之后，只保留这些名字，再交给模型。容器里其他程序可以仍在跑。

论文写，全量上每题看见的工具大约十几个，其中真正要用的大约四个，其余是干扰项。范围和均值的两句定义在数字词典。数据集卡片上还有另一句区间，和公开文件数出来的范围不完全一样，对照写在证据页。

## 一道公开题

公开题库第一行，题号 `689f4d693e212e8ef3390731`。题面问的是某款开源游戏：仓库是哪一年创建的，官网域名又是哪一年注册的，两者差几年。题面没有写下 `github_search_repositories` 这种工具 id。

`ENABLED_TOOLS` 有 15 个名字：`fetch_fetch`、`whois_whois_domain`、`mcp-code-executor_execute_code`，再加上 12 个挂在 github 上的动作（搜仓库、搜代码、搜用户、读 issue、列 issue、搜 issue、读 issue 评论、读仓库、读提交、列提交、读文件、列分支）。

参考调用打了 5 次，用了 5 个不同名字：`github_search_repositories`、`github_get_repository`、`fetch_fetch`、`whois_whois_domain`、`mcp-code-executor_execute_code`。其余 10 个都在 github 上，这条解法没有用。github 的目录里一共 33 个动作。这一题只露出 12 个，解法只用了 2 个。模型看不见计算器，也看不见 Slack。

**15。** 是什么：这一题允许模型看见的工具名个数。不是什么：不是 github 的全部接口，也不是整个评测的接口总数。

README 里还有一条更窄的检查：允许的名字只有 `filesystem_read_text_file`，问题是 `/data/Barber Shop.csv` 的第一个词，预期回答是 Customer。filesystem 目录里有 14 个动作，这条请求只露出 1 个。它用来看调用通不通，不是题库里的典型名单。
