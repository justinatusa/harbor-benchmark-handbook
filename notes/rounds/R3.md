## 收

没有新类型，例外都能放进现有六节。

- 确定性 verifier：`automationbench`。公开树用程序断言，blog 写没有 LLM-as-judge。
- judge 模型：`mcp-atlas`。`score_claims.py` 写 LLM-as-judge，按 claim 覆盖率打分。
- GPU：`mls-bench-lite`。30 个 docker 变体里 26 题 `gpu_types = ["h100"]`。
- 出网：`toolathlon-verified`。README 要求机器能访问 Internet，抽到的一题评分调用 arXiv API。
- 多容器或图形桌面：`osworld-verified`。Docker 里是 QEMU 桌面，有 `/dev/kvm` 时把设备传进容器。
- 任务不公开：`officeqa-pro`。HF 数据集 `gated: auto`，题目和语料未下。

看起来像新轴、仍放回原节的：

- `sec-bench-pro` 要特权容器和 `/dev/kvm`，文档写不用 QEMU TCG。这是容器里的 QEMU，放进「多容器或图形桌面」已有的 KVM 传递。非图形 KVM 只有这一例，不开新轴。
- `exploitgym` 的 agent、target、controller、防火墙是多容器；运行期只放行 LLM API，是出网 allowlist。
- `spreadsheetbench-2` 可视化要在 Windows 上用 Excel/WPS COM 导出图。确定性 verifier 一节已经准备 Windows Excel；可视化分另调 judge。
- `3dcodebench` 要本机 Blender 5.0，清单没有 Dockerfile。这是单个 slug 的 environment 准备。SigLIP-2、DINOv3、Uni3D 放进 GPU。不开新轴。
- `omnidocbench` 的 CDM 用 pdflatex、ImageMagick、Ghostscript，仍是程序比对。
- `critpt` 论文写确定性脚本，正式分数要交私有评分服务，公开仓没有该脚本。放进任务不公开。
- `toolathlon-verified` 的 kind 和 `deployment/` 本地应用是多容器。
- `deepswe-v1-1` 的清单写 tag 只有 `v1.0.0`，没有名为 `v1.1` 的 tag。不写成原生可接。verifier 另起容器是 `environment_mode = "separate"`，不是新依赖。HF `datacurve/deep-swe` gated 已在任务不公开那一节。登记距离保持轻适配。

原生可接五行都有 `task.toml` 证据：`terminal-bench-4-0` 66 个，`terminal-bench-2-1` 89 个，`swe-bench-pro` 642 个，`mls-bench-lite` 30 个 docker 变体，`swe-atlas` 三轨都有。`swe-atlas` 的 Refactoring 没有 `dataset.toml`，qa 与 tw 有。没有一行是清单里既无 `task.toml` 也无 `dataset.toml`。不改 registry 距离。
